## Контекст проекта (этого достаточно, не запрашивай больше)

**Что это.** Бот «Оборудыш» переезжает с кнопочного интерфейса в Telegram Mini App (web-app). Бот остаётся для уведомлений. Функции: бронь оборудования, бронь студии-аудитории 626, админка.

**Роли пользователей** (по возрастанию доступа): СО/ССФ → стажёр → активист. Роль назначает админ при верификации, автоматически не понижается. Отделы (Фото/Видео/Дизайн/СММ/Прод/VFX) есть только у участников Media BMSTU. Организации СО/ССФ выбираются из списка (Студсовет СМ, ССО 10, BEST и т.д.) + «Другое». Есть админы и старшие админы.

**Регистрация**: первый вход → регламент → «Согласен» → профиль (ФИО, организации, отделы) → верификация: Media BMSTU — автоматически по таблице участников; СО/ССФ — вручную старшим админом (он же ставит роль). Отклонение → повтор через 3 часа. Есть чёрный список.

**Заявка на оборудование**: календарь (месяцы листаются, бронь может пересекать месяц; загруженность дней подсвечена) → время из слотов 09:00–21:30 шаг 30 мин → каталог (категории-чипсы, поиск, «свободно N из M», количество) → корзина → детали (мероприятие обязательно, комментарий нет, чекбокс «ответственный за медиа») → подтверждение. Правила: заявка минимум за 2 дня; носители (карты/SSD) отдельной заявкой; возврат в воскресенье и вечер субботы (после 18:00) запрещён; предупреждение о комплекте (камера без объектива, свет без аккумов). Позиции «уровня главы» и заблокированные категории берутся по паролю (пароль в методичках НЕ раскрывать — писать «узнайте у главы отдела»); админ видит пометку «взято по паролю».

**Статусы заявки**: Новая → Назначен куратор → Согласована → Выдана → Возврат на проверке → Закрыта (+ Отклонена / Отменена / автоотмены: 3 дня без решения, срок получения истёк). До согласования пользователь может редактировать и удалять заявку. В карточке заявки — переписка с куратором (обе стороны получают уведомления от бота). Сдача — обязательно 3 фото; возврат с комментарием админа уходит на проверку старшим, без комментария — в архив.

**Экземпляры**: у позиций в нескольких экземплярах есть теоретические номера 1..N. Пользователь номер не видит. При выдаче система предлагает админу минимальный свободный номер (свободны 3,5,6 → предлагает 3), админ может выбрать другой свободный.

**626**: дата через календарь, слоты 🟢/🔴, пересечения запрещены; допы: хромакей, циклорама, чёрная ткань, помощь Media Tech, «Другое» (свой текст). Согласуют только старшие; после согласования любой админ может стать куратором → переписка. Сдача — 3 фото, «Спасибо, приходите ещё».

**Админ**: очереди (без куратора / мои / сегодня), карточка заявки: Стать куратором → Согласовано/Отклонено → Выдать (чек-лист позиций с номерами экземпляров) → Принять возврат. **Старший админ** (заявки на оборудование НЕ ведёт): согласование 626, верификация с назначением роли, чёрный список, добавление оборудования, блокировка категорий на срок, рассылки, статистика.

**«Задать вопрос»**: свободный текст, можно анонимно, без лимита.

## ЗАДАНИЕ 1 — Python-парсер каталога из Google-таблицы

Напиши скрипт `parse_equipment.py` (Python 3, только стандартная библиотека + `requests`), который:

1. Скачивает CSV: `https://docs.google.com/spreadsheets/d/1cPFCRkBSb_R25b5ZB2aJvK32gd0WUNa0Rx2VriAW0Wo/export?format=csv&gid=0`
2. Структура листа (реальный фрагмент):
```csv
Категория,Подкатегория ,Короткое имя,Полное наименование,Общее кол-во,Допуск,,,,...,626
Камеры,Sony,a6700,Беззеркальная камера Sony A6700 body,1,НЕ ВЫДАЕТСЯ,,,...
,,а7м4,Фотоаппарат Sony Alpha ILCE-7M4 Body,1,Активист Media BMSTU,,,...
,,Маленькая Сонька,Камера Sony ZV-E10,2,Стажер Media BMSTU + СО/ССФ,,,...
,,,,,Стажер Media BMSTU + СО/ССФ,,,...
```
   - Брать только первые 6 колонок, остальные (включая колонку «626» справа) игнорировать.
   - Пустые «Категория»/«Подкатегория» наследуются от строки выше (объединённые ячейки).
   - Если у позиции «Общее кол-во» > 1, за ней идут строки-экземпляры (пустые имена, заполнен только Допуск). Это теоретические номера: сама строка позиции = экземпляр №1, следующая = №2 и т.д. У каждого экземпляра свой допуск.
   - Строки совсем без данных пропускать.
3. Маппинг «Допуск» → `level`: `НЕ ВЫДАЕТСЯ` → `"none"`; содержит `Активист` → `"акт"`; содержит `Стажер` → `null` (доступно всем); содержит `глава`/`Глава` → `"глава"`. Другие значения — выводить в консоль как предупреждение и ставить `null`.
4. Пишет два файла:
   - `equipment.json`: `[{"cat": "...", "subcat_of": {"короткое имя": "подкатегория", ...}, "items": [{"short": "...", "full": "...", "total": N, "level": null|"акт"|"глава"|"none", "units": [{"n": 1, "level": ...}, ...]}]}]` (units — только если total > 1)
   - `catalog.js`: `window.OBORUDKA_CATALOG = <тот же массив, но без subcat_of и units, поля: cat, items:[{short, full, total, level}]>;` — этот файл кладётся рядом с `prototype/index.html` и прототип подхватит его автоматически. Позиции с level `"none"` в catalog.js не включать.
5. Запуск: `python parse_equipment.py` без аргументов, файлы создаются рядом. Печатает сводку: категорий, позиций, экземпляров, предупреждения.

Также дай короткую инструкцию для Windows 11: как поставить Python с python.org (НЕ из Microsoft Store), поставить requests и запустить скрипт (на машине Python сейчас нет).
