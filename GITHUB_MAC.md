# Оборудыш: новые версии через GitHub с Mac

Рабочая папка остаётся `/Users/aleksejdavydov/Projects/Оборудыш`. Репозиторий — `misterfrukt3/Oborudsh`, ветка `main`. Повторно клонировать проект или переименовывать папку не нужно.

Эта инструкция относится только к Оборудышу: его код, GitHub-репозиторий, сервис и данные обслуживаются отдельно. ТехСценарий был приведён владельцем как пример процесса обновления и не входит в эту настройку.

## Как выпускаем изменения

1. Разработчик проверяет состояние локальных файлов и актуальную `origin/main`, сохраняет уже сделанные правки.
2. Вносит изменения в этой же папке, запускает подходящие проверки и обновляет `AGENTS.md`, `STATUS.md` и инструкцию выкладки.
3. Самостоятельно создаёт коммит и отправляет его в `origin/main`. В отчёте даёт hash и список действий для сервера. Пользователю не требуется вручную коммитить файлы.
4. Обновление сервера выполняется отдельно по `DEPLOY.md`. Успешный push не означает, что бот уже обновлён.

Не использовать `git reset --hard`, `git clean`, force push или повторное клонирование поверх рабочей папки. Если есть конфликт или расходятся версии, сначала сохранить и разобрать изменения.

## Получить опубликованные изменения в этой же папке

```bash
cd '/Users/aleksejdavydov/Projects/Оборудыш'
```

```bash
git status --short --branch
```

Если есть незакоммиченные правки, сначала сохранить их отдельным коммитом либо разобрать с разработчиком. Затем:

```bash
git pull --ff-only origin main
```

```bash
git rev-parse --short HEAD
```

`--ff-only` останавливает обновление при расхождении истории. Настройки, базы и локальные окружения не входят в коммиты и остаются в существующих папках. Перед обновлением разработчик проверяет, что новые коммиты не добавляют рабочие `.env`, базы или локальные каталоги в Git.
